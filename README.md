# MARS Pro

MARS Pro 是基于 PyQt5 的旋转体表磁测量分析系统，适配 **3Axis_MARS v1.x 固件**（USB CDC 虚拟串口），支持 X/Y/Z 三轴滑台 + R 轴卡盘旋转电机的四轴控制。

当前仓库根目录就是 MARS pro/ 本身。

> MARS Pro 是从 [MARS](https://github.com/IceSugarZxy/MARS)（V3.5 固件）升级而来，通信协议、硬件架构、控制方式均有重大变化。

2. **分析指标一律实时重算**：CSV 不再写 `=== 分析结果 ===` 快照段；历史数据面板与

   `core/defect_fingerprint.analyze_run`（= 闭合点裁切 → 波形分析），与实时测量、数据比对
   完全同一条链路。同一份数据在任何入口看到的指标一致，且始终跟随最新算法，改代码后无需重存数据。
3. **误差口径（说明性，非本次改动）**：MARS 的 N/S 极误差、N/S 极间隔误差采用 **RSD**
   （样本标准差 `÷ (k−1)` 后 `÷ 均值 × 100`）；平野（千石）设备导出的"误差"是 **MAD**
   （平均绝对偏差 `÷ 均值 × 100`）。两者都是相对波动率、量纲一致，但数值不能直接横向比。

## 功能概览

- 串口连接、自动扫描串口和启动时自动连接
- X/Y/Z 三轴滑台实时位置查询（M~ 命令，1.5s 轮询）
- 运动命令自动绝对->相对换算（X+5000~ / Z-3000~），START 确认 + DONE 信号等待，位置追踪智能超时（堵转检测）
- B~ 采集两段超时（启动 30s / 中断 2s）自动结束；等待首数据期间不轮询 `M~`，`_measurement_active` 标志隔离文本解析器与二进制数据流
- 采集速度三档（高精度 / 均衡 / 高速，默认**均衡**）：改用 `ACQCFG`+`ADCRATE` 参数指令（不再发 `MODE<n>~`，参数见「采集档位」），切换档位按 `ACQCFG → ADCRATE → PGA → IDAC` 顺序下发且重发当前 PGA/IDAC 组合，B~ 发送前 flush_write_queue 同步刷新写队列确保指令实际发出
- 旋转测量经闭合点裁切的一圈波形按 0-360° 显示；单周期幅值包络补偿后同步用于波形、CSV 与分析
- 测量完成对话框常驻，用户手动确认关闭

## 与 MARS（旧版）的主要差异

| 项目 | MARS (V3.5) | MARS Pro (v1.x) |
|------|-------------|-----------------|
| 滑台轴 | X/Z 双轴 | **X/Y/Z 三轴** |

### 随包附带的历史波形数据

`MARS.spec` 会把 `data/plot_data/<日期>/` 打进 `dist/MARS_Pro/data/plot_data/<日期>/`，
运行时“历史数据”面板可直接加载。默认打 `data/plot_data` 下**最近的一天**，可用环境变量指定：

```powershell

pyinstaller MARS.spec --clean --noconfirm
```

`MARS.spec` 按自身所在目录解析工程路径（取 PyInstaller 注入的 `SPECPATH`），
因此在任意工作目录下 `pyinstaller <路径>/MARS.spec` 都能正确打包，不必先 `cd` 到工程根目录。

### 双码道解算依赖的原厂 DLL

`MARS.spec` 会把 `vendor/iC-MU150/` 整个目录打进 `dist/MARS_Pro/vendor/iC-MU150/`，
“双码道解算”页面按 exe 同级的这个路径固定加载 `MU_3SL_INTERFACE_64.DLL`（不再让测试人员选库）。
**构建前请确认 `vendor/iC-MU150/MU_3SL_INTERFACE_64.DLL` 存在**，否则打出的包点「解算」会提示找不到 DLL。
该 DLL 属于 iC-Haus MU150 SDK，受原厂许可约束，仓库不跟踪（`.gitignore` 已忽略 `vendor/`），
需要各自从 SDK 拷贝到本地 `vendor/iC-MU150/` 后再打包。

### ⚠ 必须在纯 ASCII 路径下构建

PyQt5 自带的 Qt 5.15 在**安装路径含中文**时，`QLibraryInfo` 返回的插件路径会被破坏
（`旋转体表磁测量分析系统` → `???????????`），PyInstaller 的 Qt hook 检查该路径时会直接报
`Qt plugin directory ... does not exist!`。**工程目录本身可以含中文，但构建用的 Python
环境不能。** 做法：把 `.venv` 复制到 ASCII 路径（如 `C:\mars_build\`），用复制后的解释器构建：

```powershell
robocopy ".venv" "C:\mars_build\.venv" /E /XD __pycache__ /NFL /NDL /NJH /NJS
robocopy "." "C:\mars_build" src vendor data\plot_data\20261119 一致性测试 MARS.spec /E
cd C:\mars_build
C:\mars_build\.venv\Scripts\python.exe -m PyInstaller --clean --noconfirm MARS.spec
```

如果 Python 本身已装在纯 ASCII 路径（如 `D:\Python\Python311`）并装好 `requirements.txt`
与 `pyinstaller`，可以直接用它构建，不必再复制 `.venv`：

```powershell
robocopy "." "C:\mars_build" src vendor data\plot_data\20261119 一致性测试 MARS.spec /E
cd C:\mars_build
set MARS_BUNDLE_DATA=20261119
python -m PyInstaller --clean --noconfirm MARS.spec
```

构建产物可正常从中文路径运行（Qt 运行时按 DLL 所在目录找插件，不受该问题影响），
把 `C:\mars_build\dist\MARS_Pro\` 拷回任意位置即可。

### 发布包命名

分发时把 `dist/MARS_Pro/` 整个文件夹压缩为 `dist/MARS_Pro_<YYYYMMDD>.zip`（例：

## 采集档位（ACQCFG / ADCRATE）

三档采集参数只通过参数接口下发，不再使用固件封装的 `MODE<n>~`：

| 测试速度 | ACQCFG | ADCRATE | 每圈点数 |
|---|---|---|---|
| 高精度（0） | `ACQCFG50,260,1,4~` | `ADCRATE2400~` | 131072 |
| 均衡（1，默认） | `ACQCFG200,579,2,4~` | `ADCRATE7200~` | 65536 |
| 高速（2） | `ACQCFG200,879,4,4~` | `ADCRATE4800~` | 32768 |

`ACQCFG` 四个参数依次为**起始转速、目标转速、分频、每圈边沿数**。切换档位时按下发顺序
`ACQCFG → ADCRATE → PGA → IDAC` 执行；每次改档都会重发上位机当前选定的 PGA/IDAC 组合，
避免固件里上一次残留的档位覆盖上位机设置。

对应实现：`src/core/serial_command.py`（`TEST_SPEED_TO_COMMANDS`）、
`src/core/data_process.py`（`SAMPLES_PER_REV`）。

### 一圈点数：收到多少就是多少（默认不裁切）

固件按“精确一圈”出流，**每圈点数由采集档位决定、三档各不相同**（高精度 131072 / 均衡 65536 / 高速 32768），
所以上位机不再做闭合点裁切：收到 N 点就按 `i·360/N` 映射成整圈，保存的 CSV 行数与收到点数一致
（CSV 头部额外写一行 `一圈点数,<N>` 便于追溯）。每轮都会在日志里留一条体检信息，标称值取当前档位：

```
# 高速档（32768）
一圈数据体检: 点数=32768（档位标称=32768，收到=32768，裁切=否）, 首尾差=0.041 mT（峰峰 0.21%）, closure_found=False
# 均衡档（65536）
一圈数据体检: 点数=65536（档位标称=65536，收到=65536，裁切=否）, 首尾差=0.031 mT（峰峰 0.15%）, closure_found=False
```

点数与该档位标称不一致时会额外 `WARNING`（例如均衡档只收到 32768 点）。旧行为（在标称尾点 ±0.2% 范围内
找首尾最闭合的点并据此截断，会得到 32756 这类点数）保留在 `closure_trim` 开关后面：`configuration.txt`
写 `closure_trim:1` 即恢复；默认 `0`。双码道解算与本项无关：它读取文件时保持原始点数，两轨点数不同时按**较多的一侧**配对（见下一条）。

## 光电贴靠标定（LSBASE / LSTH）

配置面板的「贴靠基准」和「贴靠阈值」用于标定光电位移传感器的模拟下压保护。
静态值、当前值和下降量阈值均使用 ADC 原始计数，上位机阈值默认 `25`、可设为 1–4095，与 XYZ 限位开关无关。

| 界面控件 | 协议指令 | 操作条件与结果 |
|---|---|---|
| 贴靠基准 | `LSBASE~` | 探头未下压时点击；记录当前值为 `STATIC`，保存到设备 Flash |
| 贴靠阈值 | `LSTH<n>~` | 输入 1–4095 后点击“设置阈值”，默认 25，保存到设备 Flash |

固件按有符号下降量执行两级保护：

```text
DIFF = STATIC - 当前ADC
第一级停机：DIFF > THRESH
第二级停机：DIFF > 2 × THRESH
```

标定步骤：

1. 连接设备并停止 XYZR 全部电机，确认探头处于未下压状态。
2. 点击「贴靠基准」，等待界面显示新的 `STATIC`、`THRESH` 和接近 0 的 `DIFF`。
3. 在「贴靠阈值」输入所需值，点击“设置阈值”，上位机发送 `LSTH<n>~`。
4. 确认界面显示的 `THRESH` 与输入值一致，且 `SAVED=1`、`VALID=1`；需要重新读取时发送 `LIGHTSW~`。

界面在等待设备回信期间会临时禁用设置按钮和阈值输入框；超过 4 s 未回信时提示检查固件版本。
贴靠时 ADC 应下降、`DIFF` 应增大。运动或采集期间设备可能返回 `LIGHTSW BUSY`，
此时应停止运动或采集后重试。旧两点版本的 `PRESS`、`ABS_DIFF` 字段已不再使用。
详细回信和错误定义见
[`USB_CDC_通信协议手册.md`](USB_CDC_通信协议手册.md) 顶部的 LIGHT_SW 章节。

- Y 轴：`640.53` 脉冲 / mm（与 X 轴统一标定）
